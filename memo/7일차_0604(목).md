# 카프카 개념 설명
- AI 처리할때 실시간 데이터 처리 되게 중요, 데이터가 파이프라인으로 구성되어 실시간으로 자동으로 흘러가야 한다.
- 데이터가 단일변수만 있는 게 아니라 굉장히 많고 데이터 양도 많아서 실시간 처리하는게 어려운 점이 어느 기업에 가던 난제이다.
- 카프카 데이터 스트리밍 처리를 사용한다. 프레임워크.
- 오늘은 카프카 배워보고 실제 구현 실습 진행할 것이다.

- 위와 같이 구성된다.
- 브로커:  각각의 클러스터 서버이다. 브로커(각각 클러스터)에 보낸 내용을 저장한다. 서버가 끊겨도 이쪽에서 데이터를 다시 가져올 수 있다. 실제 통신서버 운영시 끊어지는 경우가 많은데 얘는 끊어져도 브로커에서 다 저장하고 관리하기 때문에 이어서 연결해서 다시 실행할 수 있다.
- 주키퍼 클러스터: 브로커를 관리해주는 오케스트레이션 역할을 한다. 스케줄링 등 운영 관리. 서버가 끊기는 부하를 계산해서 오케스트레이션을 해주기 때문에 서버 운영관리 측면에서 효율적이다.
- 프로튜서: 데이터 보내는 역할. 데이터를 카프카 클러스터에 저장. 센서1 토픽에 데이터 넣어서 전달한다.
- 컨슈머: 데이터를 받는 역할. 센서1이라는 토픽정보 프로듀서/컨슈머 간에 토픽이 맞아야 함.
- 파란 네모: 토픽, 데이터 이동 경로. 
- 구조가 설비단 실시간 데이터 갖고와서 보내주는 통신인 MQTT 통신과 비슷하다.
- TCP/IP, FastAPI는 엔드유저 사용할때 많이 사용하는 거라고 보면 되고, 카프카도 엔드유저에 사용되기도 하지만 데이터가 실시간으로 발생하는 그 쪽에서 센서로 땡겨와서 AI서버나 디비에 실제로 저장해주는 단계에서 조금 더 많이 사용된다.

## 카프카 되게 중요하다
- AI의 꽃이다. 실시간이 되게 중요하다. 문제가 나타나고 나서 분석하는 것은 의미없다. 실시간 분석해서 어떻게 조치해야 하는지가 중요하다. 그 떄 실시간으로 처리할때 카프카를 많이 사용한다.
- 분석 끝나면 mlops -> git/jenkins 인프라 구축 진행할 예정이다.
## 경력자들 면접볼때
- 역량 파악 기술질문 꼭 물어 봤었다. 데이터 실시간 처리 어떻게 하셨는지
- 거기서 올바른 대답을 한 사람들은 좋은 점수. 제대로 못하면 마이너스 점수를 줬었다.
