## 1. 파일 세팅
### [1] train.py 파일 생성 및 실행
```py
cat > train.py << 'EOF'
import numpy as np
import pickle
from sklearn.ensemble import RandomForestClassifier

X = np.random.randn(200, 1)
y = (X[:, 0] > 0).astype(int)

model = RandomForestClassifier()
model.fit(X, y)

with open("model.pkl", "wb") as f:
    pickle.dump(model, f)

np.save("reference.npy", X)

print("model.pkl, reference.npy 생성 완료")
EOF
```
![alt text](image-646.png)
- 실행: `python3 train.py`

### [2] app.py 파일 생성 및 실행
```py
cat > app.py << 'EOF'
from fastapi import FastAPI
import pickle
import numpy as np

app = FastAPI()

with open("model.pkl", "rb") as f:
    model = pickle.load(f)

@app.get("/")
def home():
    return {"message": "AI Model API is running"}

@app.get("/predict")
def predict(value: float):
    X = np.array([[value]])
    pred = model.predict(X)[0]
    return {
        "input": value,
        "prediction": int(pred)
    }
EOF
```
- 실행: `python3 app.py`

```py
EOF
```

### [참고] 필드에서의 서버 환경
- 온프레미스(내부에 여러 서버 구축), 클라우드, 하이브리드(온프레미스+클라우드) 로 나뉜다.
- 큰기업들은 보안이 강해서 외부망에 데이터를 연결할 수 있는 상황이 거의 없다.
- 내부 로우데이터를 웬만하면 방화벽으로 막아놔서 못내보낸다.
- `분석엔진서버(학습서버)`: 내부에 서버1(CPU), 서버2(GPU), 서버3(스토리지), 서버4, ... 이런 식으로 분산시켜 구축한다. (온프레미스 환경/서버실) ==> 분석엔진 서버에서는 실시간 데이터 땡겨와서 학습까지 이루어진다.
    - 다 클라우드에 올리기에는 비용이 어마어마하기 때문 + 보안 --> 보통 온프레미스로 구축
- `추론서버`: [학습 결과], [추론 모듈 <-> endpoint] <-> `엔드유저 웹서비스`
    - 추론서버는 온프레미스 또는 클라우드 형태로 구축된다. 보안에 문제 없는 이유: 로우 데이터를 보낼 일이 었기 때문에 보안적으로 조금 문제가 덜 해진다. 그래서 클라우드로 구성하기도 한다.
- 추론서버에 학습결과 업데이트 하는 것 까지는: Batch Scheduling 으로 계속 작업 돌림
- 추론서버와 엔드유저 사이는 Real Time 으로 처리된다. (실시간)
- 위와 같이 하이브리드 형태로 시스템/플랫폼 환경이 구축된다. 
- 프로젝트 진행 시, 필드 환경을 최대한 모사하는 게 좋다. 필드 형태와 비슷하게 진행한다.

### [TIP] Git 운영 팁
- 서비스 레벨에서 말씀드리면 우리 팀만 있는 게 아니라 `여러 팀, 여러 센터`가 있다.
- 여러 조직들이 있고, 그런 경우 각 조직마다 서비스를 런칭하기 위해 APP을 개발한다고 가정한다.
- [개발조직] 조직1->APP1, 조직2->APP2, 조직3->APP3, ... (==> GIT/패키징팀)
- 근데 이 앱은 하나의 플랫폼에 관리해야 하는 앱인 경우 하나의 플랫폼은 빌드 패키징 팀이라는 게 있다.
- [패키징팀] 전체 앱들을 GIT으로 모아 관리한다. -> 젠킨스
- 젠킨스: [빌드->코드테스트->패키징] ==> 배포 ==> Service
    - 이 부분은 단계별로 오류가 매우 많이 발생하기 때문에 별도의 전문 팀이 관리해 주어야 한다.
- 업무 체계가 잘 시스템화 되어 있으면 이 부분은 패키징 팀이라는 별도의 팀이 관리한다. -> 개발팀은 개발+푸시만 한다. [큰 기업의 케이스]
- 근데 작은 기업들은 다 해야됨.
- 대기업이 좋지 않은 부분: 바보가 됨. 내가 해야 하는 것만 딱 하면 됨
    - 엔지니어는 여러 툴들을 다 아는것이 유용하다.
    - 그 회사는 업무 스펙트럼이 넓어 -> 이것밖에 안 해봤기 때문에 다양한 스펙트럼을 맞출 수 없다.
    - 위와 같은 경우 많이 발생한다. (경력 쌓기 더 안 좋은 것 같다고 한다.)

- 그 부분에 대해서 노력 및 표현을 해 보는 것을 추천함.
- 면접에서 보는 것
    - 1) AI 정체성 확립(재미삼아 하는게 아닌지) 
    - 2) 커뮤니케이션 스타일 괜찮은지 
    - 3) 문서 역량이 좋은지 
    - 4) AI 역량이 있는지 
    - 5) 이 쪽 분야 도메인 사전 지식이 있는지 
    - 6) 안 좋은 상황을 주고 어떻게 극복 하는지 테스트 (조직에 적응을 잘 할 수 있을지)
    - 최종 점수를 total 으로 인사팀에 넘겼다.
- LG에너지솔루션에서는 그렇게 봤지만 다른 기업들에서도 비슷하기 때문에 그런 관점으로 준비해야 한다.

### 프로젝트
- 기획 -> 브레인스토밍(산업적으로 효과 낼 수 있는 주제를 선정) -> 주제선정 -> 주제 내용 구체화 작업
    - 1) 데이터가 있는지, 어떤 데이터를 활용해야 할지 조사
    - 2) 이 데이터를 가지고 실제 산업적 효과 낼 수 있는지, 문제가 있는지 문제 정의를 한다.
    - 2-2) AI 를 가지고 어떤 효과를 낼수 있는지 방향성을 제시
    - 3) 기술적인 구체화를 시킨다. end-to-end 사용자가 사용할 수 있는 수준(엔드유저)의 프론트 서비스까지 나와야 함(시스템화)
    - 3-2) 시스템을 구축하기 위한 시스템 설계, 데이터 파이프라인 프로세스 구성/설계, 문제를 풀기 위해 어떤 어프로치를 통해 모델 사용했는지에 대한 근거, 설득하기 위한 AI 아키텍처/알고리즘 측면에서도 기획 및 작성 해야함, 테스트/검증, 산업적 기대 효과, 프로젝트 기술을 가지고 비즈니스 모델 관점에서 활용할 수 있는지까지 제시할 것이다. (회사에서 사용하는 형식/회사에서 바라보는 관점으로 진행 예정)
    - 제일 중요한 것: 타겟과 어떤 AI솔루션을 활용할지 문제 정의를 잘 해야 함. + 어떻게 풀어나갈지(아키텍처/시스템/...등등) 효과를 제시해야 한다.
- AI 전문가: 문제를 많이 접해 보았기 때문에 생긴 기술적 노하우를 많이 갖고 있는 사람들
- 항상 문제 정의를 잘 하고, 그걸 기술적으로 어떻게 풀었었는지에 대한 경험을 많이 쌓아야 한다.
- 제약이 많아도 극복하고 해내야 함. 그럴려면 중간에 실패를 많이 접하고 혼나면서 성장.
- 젠슨황 유퀴즈에 왔다. 똑똑하게 애를 키우는 법? -> 공부할 환경만 제공해주고, `많은 실수/실패 많이 접하게 해줘라`. -> 실패 극복해 나가면서 성공

### 요즘 KPI 매기는 법
- 논문 내용을 가지고 양산에 몇번 적용을 했는지. 가지고 평가를 한다.
- 효과 80->90% 몇 퍼센트 개선 했는지. 이런 식으로 양산 기준으로 평가한다. 필드에 나가서 일한다.
- 현장에서의 문제를 알아야 개선점을 찾을 수 있다.
